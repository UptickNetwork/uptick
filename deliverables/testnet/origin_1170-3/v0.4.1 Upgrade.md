# Uptick Origin Testnet – v0.4.1 Upgrade Announcement

Dear Uptick Origin Validators,

We are excited to announce that the Uptick Origin testnet will be upgraded to v0.4.1:

- Target Block Height: 14,986,000 *(proposed — to be confirmed with the governance proposal)*
- Estimated Time: September 18th, 2026, at ~10:00 UTC
- Commit Hash: `cc68b3d24ab7506186f8ec89350df1271a2c3451`
- Tag: `v0.4.1-fix`

> **Important — verify your binary's commit hash.** An earlier `v0.4.1` release was published from the wrong commit (`81bf79e…`). Binaries built from it **cannot execute the v0.4.1 upgrade plan** and must be replaced. The correct binary reports `commit: cc68b3d24ab7506186f8ec89350df1271a2c3451` — check with `uptickd version --long` before the upgrade height.

## Changed

v0.4.1 repairs state left behind by the v0.4.0 migration and hardens the chain. All state repairs run automatically at the upgrade height — no manual action is required:

- EVM static precompiles are activated (bank, staking, distribution, ICS20, gov, slashing, bech32, p256) — v0.4.0 shipped the `ActiveStaticPrecompiles` param empty, so every custom static precompile was inactive. The vesting precompile (0x803) stays off.
- The ICA controller submodule is enabled, preserving existing controller params.
- The feemarket base fee is repaired: the legacy ethermint `math.Int` encoding was being read as `math.LegacyDec` (scaled by 10^18), which would have permanently baked a 10^-9 wei base fee into the store.
- Redundant ERC721 UID reverse-index entries from v0.3.3-era conversions are pruned (only provably duplicate entries; conflicts and orphans are kept and reported).
- Security hardening: a strict one-to-one NFT mapping for ERC721/CW721 conversions (blocking the release of module-escrowed tokens to a colliding NFT id), fixed ERC721 IBC refund ordering, and rejection of malleable high-s EIP-712 signatures (EIP-2).
- Keplr compatibility: legacy ethermint EIP-712 type URLs (`ExtensionOptionsWeb3Tx`, `ethsecp256k1.PubKey`) are mapped at runtime.
- Genesis export resilience: degraded exports write a machine-readable `export-issues.json` report next to the node home, and `uptickd export` again writes only the genesis to stdout.

> **Note:** the chain is already on the v0.4.0 state, so only the **`v0.4.1`** governance plan is required — do **not** re-propose `v0.4.0`. (A chain coming from v0.3.x would need both plans in order; that does not apply here.)

## For Validators Running Cosmovisor

Please refer to our [Cosmovisor](https://upticknft.gitbook.io/uptick-network-documentation/guides/quickstart/cosmovisor) Setup Guide.

Please Note: Cosmovisor will perform a full backup unless you set the environment variable: UNSAFE_SKIP_BACKUP=true

**Note the directory name is `v0.4.1`** — it must match the upgrade plan name, even though the git tag is `v0.4.1-fix`:

```bash
# make a dir if you've not
mkdir -p $DAEMON_HOME/cosmovisor/upgrades/v0.4.1/bin

# Download the source code and build it
git clone https://github.com/UptickNetwork/uptick.git
cd uptick
git fetch --tags
git checkout v0.4.1-fix
make build

# Copy binary files
cp ./build/uptickd $DAEMON_HOME/cosmovisor/upgrades/v0.4.1/bin/

# View version should be v0.4.1
$DAEMON_HOME/cosmovisor/upgrades/v0.4.1/bin/uptickd version --long
# commit: cc68b3d24ab7506186f8ec89350df1271a2c3451
```

## For Validators NOT Using Cosmovisor

The chain will halt at the target block. Please manually update your binary as follows:

```bash
# Download the source code and build it
git clone https://github.com/UptickNetwork/uptick.git
cd uptick
git fetch --tags
git checkout v0.4.1-fix
make install

# View version should be v0.4.1
uptickd version --long
# commit: cc68b3d24ab7506186f8ec89350df1271a2c3451
```
